# WorkBuddy 每日签到 · 功能介绍

一个浏览器扩展，装一次，之后每天自动把 WorkBuddy 的积分领了。不需要令牌、不需要命令行、不需要保持某个页面打开。

## 能做什么

- **每日签到**：每天定时领取（+100 积分），已签过会自动跳过，重复运行不会多领也不会报错。
- **任务中心**：自动接受「去完成」的任务，开始计进度；任务真的完成后自动领奖励。
- **猫猫旅行**：派猫出门 → 到点领奖 → 立刻再派一趟，4 小时一轮循环，不是一天一趟。
- **连登兑换**：到 7 / 14 / 28 天自动领档位奖励（补登卡、积分、能量、抽奖次数）。
- **补登卡**：当月有断登且卡够时，自动补上最近的一天，保住连续天数。
- **失败提醒**：系统通知。未登录时立刻提醒并给「去登录」「已登录，重试」两个按钮。
- **日志**：全部留在本地，弹窗看最近几条，设置页可导出、复制、清空。

## 怎么做到的

- **走接口，不点界面**：直接调官方页面自己用的接口，不模拟点击，界面改版不影响；也不会触发「是否打开 WorkBuddy」那种深链弹窗。
- **复用浏览器登录态**：用你已经在网页版登录的 Cookie，不需要复制令牌、不读取 Cookie 值。
- **同源兜底**：扩展后台发请求属跨站，登录 Cookie 可能带不上；这时会自动开一个不抢焦点的标签页，从页面里发同源请求，用完立刻关掉。
- **定时用浏览器闹钟**：`chrome.alarms` 而不是常驻进程，浏览器关掉就不占资源，下次打开会补跑。
- **时间听服务端的**：猫猫回程按接口返回的 `arrive_at` 排，不是写死 4 小时；拿不到才用 4 小时兜底。
- **每步幂等**：所有领取动作失败重跑都安全，不会重复加分。
- **互不牵连**：签到、任务、猫猫、兑换、补登各自独立，某一块挂了只记一条 warn，其余照常。
- **额度用完就停手**：服务端返回「今日已达上限」时记一条 info 并撤掉当天剩余检查，不空转。
- **权限最小**：只申请 `storage` / `alarms` / `notifications` 和两个站点的访问权，不碰 `cookies`、`tabs`、`webRequest`。

## 怎么用

1. 打开 `chrome://extensions`，开启「开发者模式」
2. 点「加载已解压的扩展程序」，选 `extension/` 目录
3. 设置页里填每天几点跑（默认 09:00），保存

前提只有一个：浏览器里已登录 <https://www.workbuddy.cn/app>。

## 不做的事

- **不伪造任务完成**：服务端会校验，没做完的任务领不到；该你做的（发一次模板任务、关注公众号满 24 小时）仍然要自己做。
- **不消费你的资源**：抽奖、盲盒、积分兑换这类消耗动作不会自动执行。
- **不上传任何数据**：只访问 WorkBuddy 官方接口，不收集、不外发。
- **不保证浏览器关着也跑**：定时只在浏览器运行时触发，完全退出那天不会跑，下次启动补跑。
